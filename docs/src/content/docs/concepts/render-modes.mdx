---
title: Render input
description: Every render names a published project and template by slug, plus the data that fills the template.
---

Every render method (`render.pdf`, `render.pdf_stream`, `render.document`, and the `render_to_file` helper) takes the same keyword arguments, `PoliPage::RenderInput` in the [types reference](../../reference/types/): a `project:` slug, a `template:` slug inside it, and a `data:` hash that fills the template's placeholders.

## Required keywords

```ruby
pdf = client.render.pdf(
  project:  "billing",
  template: "invoice",
  data:     { invoice_number: "INV-001", total: 1280 }
)
```

There is no version to pick: the API renders the project's copy published in the API key's environment (see [Authentication](../authentication/)). To render your own templates, publish the project to that environment first. A missing keyword, or an unknown one, raises `ArgumentError` before any request.

## Optional keywords

- `format:` — one of `PoliPage::PageFormat::FORMATS` (e.g. `"A4"`, `"Letter"`).
- `orientation:` — `"portrait"` or `"landscape"`.
- `locale:` — a BCP 47 tag (e.g. `"en-US"`).
- `metadata:` — your own primitive-valued audit data, echoed on the `DocumentDescriptor`.
- `idempotency_key:` — overrides the auto-generated `Idempotency-Key` header.

Unset optional keywords are left out of the request, so the API's defaults apply.

## Previews and inline HTML

The API renders published templates only. To preview a template or render inline HTML while you design it, use the playground at [play.poli.page](https://play.poli.page). `client.documents.preview(id)` returns the stored HTML of a document you already rendered.

## Example

```ruby
require "poli_page"

client = PoliPage::Client.new(api_key: ENV.fetch("POLI_PAGE_API_KEY"))

invoice_pdf = client.render.pdf(
  project:     "billing",
  template:    "invoice",
  data:        { invoice_number: "INV-001", total: 1280 },
  format:      "A4",
  orientation: "portrait",
  metadata:    { customer_id: "cust_123" }
)
```
